分发形态决策

agent-evolve · CLI 内核 + Skill 为主、插件为辅

结论

不是二选一。核心逻辑做成独立 CLI 工具（pip 包），分发以 Skill 为主（跨平台公约数），插件按平台需求逐步补（自动 hook、审批 UI）。

三种形态的本质

形态本质携带什么平台绑定自动化
CLI 工具可执行程序逻辑 + 状态无手动 / 被调用
Skill指令文档规则 + 流程弱（各平台统一 skills 规范）靠智能体执行
插件宿主集成代码逻辑 + hook + UI强（每平台一套 API）自动触发、后台运行

为什么不用纯 Skill 或纯插件

  • 纯 Skill 的问题：Skill 本质是 Markdown 指令，打包不了可执行逻辑。扫描、统计、台账、备份仍需外部 CLI 承载，Skill 只能教智能体何时调用。
  • 纯插件的问题：插件绑定宿主 API（每平台一套），核心逻辑要重复实现 N 份，维护成本高，违背"任何智能体可用"的定位。

决策矩阵

需求选型
